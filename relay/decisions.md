- **2026-09-17 · contracts/handover-contract slice 4 · which command owns the checkpoint write, and how it commits** — chose **A: `/handover` (Step 4a) owns both emit and apply**, keeping the commit/push logic in the tested `_replicate_checkpoint` (not a reimplementation in handover.md bash the Python suite can't reach — the challenger's objection to "Option B"). `/handover` owns emit **and** apply because Step 1/3 already gather the exact resume state `emit` needs, and implicit apply is what makes "resume just works" true with no remembered worker step. **The slice-4 review (PR #34, `relay/reviews/pr-34-2026-09-17.md`) then reversed the commit *mechanism*** — three blockers converged on it: the original `_replicate_checkpoint` did a real **working-tree commit in the shared main checkout**, which (a) violated `docs/conventions.md`'s parallel-worktree-safe-commit invariant [arch 🔴], and (b) was functionally broken — Step 4b advances `origin/main` without advancing any local `main`, so the *second* handover's checkpoint sat on a stale local main and its push was a **permanent non-fast-forward** [backend 🔴]. Resolution: `_replicate_checkpoint` now builds the commit with the **temp-index-onto-freshly-fetched-tip** primitive (the very thing "Option B" pointed at, but kept in tested Python) — no working-tree/index/HEAD mutation, no branch guard, runs from **any checkout including the slice worktree**, so `/handover` no longer reaches into the main checkout at all. A non-ff from a sibling advancing the remote mid-lap self-heals on the next fetch-and-retry. This is the challenger's A-vs-B synthesis: B's mechanism, A's tested home. Refinements retained: (1) checkpoint-first ordering, non-blocking (resume falls back to the Markdown handover, no fail-closed); (2) **`--no-projection`** so `/handover`'s richer handover stays canonical; (3) **`--no-board`** so Step 4b owns the board commit; (4) WAL (`relay/harvest/*/results/`) gitignored. Also from the review: the security 🔴 — the Step 4a result JSON is written with the **Write tool, never shell-interpolated** (an unquoted heredoc let handover prose command-substitute before an auto-push); and the provider-neutrality scan is now **recursive** (a nested `session_id` would otherwise reach the pushed checkpoint). **Reverses if:** a future need forces the checkpoint onto a ref the temp-index-onto-durable-tip can't reach (e.g. per-worktree checkpoints), which would reopen the ref question of slice 3. Proven by the rebuilt `CheckpointDurabilityTest` (the consecutive-handover non-ff regression, any-branch replication, foreign-staged-file isolation, nested-provider rejection, CLI `main()` flags).
- **2026-09-17 · contracts/handover-contract slice 3 · which git ref the checkpoint commits+pushes to** — chose **A: commit `relay/harvest/<slug>/checkpoint.json` to main and push it, per-checkpoint (opportunistic, non-blocking — the same R1.6 discipline as `autosave`), NOT throttled to the session boundary** (autonomy: challenge). Decisive fact the brief under-weighted: `discover_active`/`resume_context` read checkpoints by walking the **checked-out working tree** (`relay/harvest/*/checkpoint.json`), not via git refs — so a fresh-device clone (which checks out `main`) only finds all active items if every checkpoint lives in main's working tree. That kills **B** (topic branch — scattered across branches the main checkout can't see, deleted on merge) and **C** (`refs/relay/checkpoints/*` — fetched by no default clone and in no working tree, so the readers couldn't see it without a rewrite). Matches R1.10 (board/handover/brief already live on main for this device-independence reason). Throttle rejected: once origin is the location that matters (cross-device), a once-per-session push leaves origin stale mid-session — reintroducing the exact loss window the feature closes; R1.5 wants "a recent durable checkpoint must always exist." A `replicated` flag records whether the push landed. **Reverses if:** a fresh-device resume is redesigned to read checkpoints via `git show`/`cat-file` from arbitrary refs (then C reopens, churn-free), OR the checkpoint is written per-worktree rather than into the shared main checkout (then B becomes natural). Both are one grep to check. Open sub-decision escalated to maintainer: per-lap checkpoint commits churn main's history — a product/workflow consequence, the maintainer's call.
