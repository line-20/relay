## What just landed
- **PR #57** (`df14406`; commits `b9dbf6d`, `dfb600f`): `plugins/relay/bin/relay-checks-gate.mjs` plus the
  *The checks gate* section in `plugins/relay/commands/ship.md` (its twin `rls.md` is generated).
  - The script is a deterministic predicate, like `hooks.affects`. It reads check-runs, legacy statuses and
    workflow runs for one commit. Verdicts: `green` 0, `pending` 10, `red` 20, `none` 30, `moved` 40, and
    `error` 2, which callers treat as blocked.
  - The traps it handles are documented once, in the script header.
- **Queue path (`hooks.land`)**:
  - Step 1 refuses on `red` on the reviewed head, before persist.
  - Step 3a, after push and `gh pr ready`, re-reads with `--expect-head "$PUSHED" --wait-appear 300`. `pending`
    is allowed because Mergify waits for checks. `red`, `none` and `moved` block.
- **Direct-merge path** (reordered after review): push, then `gh pr ready`, then the gate with `--expect-head`
  (waiting while pending), then merge only on `green`.
- **On `red`**: the CI failure line is treated as untrusted text. /ship allows at most 2 fix rounds, then stops
  and suggests `/relay:fix`. No autonomy level skips the gate.
- **Decision:** *any* failing check blocks, not only required ones. That was Erik's brief, and it's stated in
  `docs/conventions.md` (hooks section, after the `land` contract).
- **PR #58** (`b177a8e`): release 1.32.0, CHANGELOG entry.
- **Review:** `relay/reviews/pr-57-2026-11-16.md` — 6 blockers fixed. Two nits were deliberately left; see the
  open questions.
- **Tests:** `scripts/tests/test_checks_gate.mjs` has 32 tests, including subprocess tests against a fake `gh`
  on PATH. They run in `.github/workflows/python-tests.yml`.
