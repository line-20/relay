# Handover: wire checkpoint replication into the lifecycle (make cross-device resume live)

## Where we are

Relay 2.0's first stage contract — the handover→continue **resume-state contract** — is fully built. The canonical resume object is `relay/harvest/<slug>/checkpoint.json`; it is validated at both ends (slices 1–2) and, as of this lap, **git-durable** (slice 3): the runtime commits it to the durable branch and pushes it, so a pruned/foreign-machine worktree — or another device — can resume from it.

**The engine is capable but nothing on the happy path invokes it.** No lifecycle command runs `relay_harvest.py apply` (with replication), so in normal use a checkpoint is still never actually emitted+applied+pushed. Cross-device resume is *possible*, not yet *live*. That wiring is the next objective — and it is the maintainer's actual goal ("continue any step on any device, laptop or mobile").

## Context you need (so you don't re-research)

- Entry point: `apply_pending(relay_root, slug=None, board_path=None, repo_root=<repo>, replicate=True)` in `scripts/relay_harvest.py` — pass `repo_root` to get the commit+push; CLI is `python3 scripts/relay_harvest.py --repo <repo> apply [--slug <s>] [--no-replicate]`. - Emit side: a worker `emit`s a harvest result (`emit_result` / `relay_harvest.py emit` from stdin) to the WAL; `apply` turns the WAL into the checkpoint. Today no command emits — figure out whether `/handover` should emit the result *and* apply, or whether emit stays the worker's job and only `apply` is wired.
