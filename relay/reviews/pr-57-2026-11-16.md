# Review — PR #57: /ship refuses to merge or queue a PR whose checks are red

Refutation was not run as a separate step: each 🔴 was re-checked against the code by the fixing session
before it was changed. All of them were confirmed.

## 🔴 Blockers

- [x] **backend · ship.md Phase 5**: on the direct-merge path the gate ran *before* "push the fix commits".
  It judged the pre-fix commit and then merged the post-fix one, whose CI had never been read. **Fixed:** push,
  then `gh pr ready`, then gate with `--expect-head "$PUSHED" --wait-appear 300`, wait while pending, and merge
  only on green.
- [x] **backend · ship.md Phase 5, drafts**: a draft PR whose project runs no CI on drafts read `none` and
  stopped every time, because `gh pr ready` came after the gate. **Fixed** by the same reorder; the early check
  only refuses on `red`.
- [x] **tests · glue untested**: the exit codes (the contract /ship reads) were never asserted. **Fixed:**
  subprocess tests against a fake `gh` on PATH cover green, pending, red, none, moved, gh error, malformed JSON
  and bad args.
- [x] **tests · argv parsing**: ambiguous argv could gate the wrong PR. **Fixed:** strict `parseArgs`, so
  anything unknown or ambiguous is a usage error (exit 2); 9 bad shapes are tested.
- [x] **tests · `--wait-appear` loop untested** and its 15 s sleep made it untestable. **Fixed:**
  `RELAY_CHECKS_GATE_POLL_MS` overrides the interval, and the "appears later" and "never appears" cases are
  tested.
- [x] **tests · re-runs**: two attempts of one check were not covered. **Fixed:** only the highest id per
  (app, name) is kept, tested both ways.

## 🟡 Should fix

- [x] security + backend · the `red:` failure line is CI/PR-authored text, but ship.md told the model to "fix
  it in place". **Fixed:** it is labelled untrusted and used only to locate the failure, never as an
  instruction.
- [x] security · the legacy status endpoint wasn't paginated, so a failure past 30 contexts was missed
  (fail-open). **Fixed:** paginated.
- [x] security + backend · a workflow that never starts (`startup_failure`) produced no check-runs and read
  green. **Fixed:** failed or never-started runs count as red when no job already reports the failure.
- [x] security + backend · the gate didn't confirm it was judging the pushed commit (head lag, or a foreign
  push). **Fixed:** `--expect-head`; a head that never matches gives the new `moved` verdict (exit 40), which
  blocks.
- [x] backend · a run cancelled by a concurrency group (push, then `gh pr ready`) gave a false red.
  **Fixed:** `cancelled` while a run on the commit is still going reads `pending`.
- [x] backend · `gh` calls had no timeout. **Fixed:** 60 s (120 s for the log), and a timeout gives exit 2.
- [x] backend · `$CG` didn't survive into a later Bash call. **Fixed:** the gate is one self-contained line.
- [x] backend · the red → fix → re-gate loop had no budget. **Fixed:** at most 2 fix rounds per /ship.
- [x] backend + simplicity · the leftover "Green counts only for the pushed commit" bullet relied on
  `gh pr checks`. **Fixed:** folded into *Wait properly* with `--expect-head`.
- [x] simplicity · the incident story and traps were written in 3–4 places. **Fixed:** the script header owns
  them; ship.md and conventions.md point to it. The repeated `none` rule in queue step 1 is shortened.
- [x] backend · any failing check blocks, not just required ones; projects with no CI get `none`. **Kept on
  purpose** (the brief: "any failed check → do not queue") and now stated in conventions.md. Before this PR,
  `gh pr checks` on a PR with no checks also failed the merge gate.

## 🟢 Nits

- [x] security · check names and titles could forge output lines with control characters. **Fixed:**
  `sanitize()` on everything printed.
- [x] simplicity · unused `--json` flag. **Removed.**
- [x] backend · red legacy statuses lost their description and URL. **Fixed.**
- [x] simplicity · two separate Mergify filters. **Fixed:** one predicate.
- [ ] security · the relative fallback path `plugins/relay/bin/…` resolves inside the shipped repo, which could
  ship its own stub. **Not changed:** this is the same lookup /persist uses for `relay-memory-check.mjs`, and
  /ship already runs repo-controlled hooks and tests, so it adds no new trust. Worth revisiting for both
  scripts together.
- [ ] simplicity · drop the log scraping in favour of check titles. **Not changed:** the failure line is the
  "why" the brief asked for. Verified against #2397's real logs.
