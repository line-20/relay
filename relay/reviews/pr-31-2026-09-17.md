# Review — PR #31 · resume-delta field-level validation

Fan-out: security (always-on), backend-developer, test-engineer — applicable set for a Python
validation change (no frontend/API/DB/i18n surface). All findings below were fixed in the fix pass
and re-verified; the suite is green at 31 tests.

## 🔴 Blockers (resolved)

- [x] **present-`null` `in_flight`/`next_slice` accepted → renderer crash → wedged WAL replay** — `scripts/relay_harvest.py`. Raised independently by **backend** and **security** (both ran it). `rd.get(k)` can't distinguish an absent key from a present `null`, so the `is not None` guards skipped it; `_render_handover_md` only falls back for *absent* keys, so a present null reached `"\n".join([...])` → `TypeError`, and `apply_pending` catches only `HarvestError`, so it escaped and re-crashed every WAL replay. **Fix:** `_validate_resume_delta` now gates each field on key *presence* (`"k" in rd`), so a present null is rejected; `_render_handover_md` hardened to treat a null `in_flight`/`next_slice` as clean/fallback (defence in depth for legacy on-disk checkpoints). Tests: null cases added to the rejection set + a render-doesn't-crash test.

- [x] **fail-safe not proven through the real `emit_result` write path** — `scripts/tests/test_relay_harvest.py`. The shape test only called `validate_result` directly, not the write path, unlike `test_malformed_result_fails_safe`. **Fix:** added `test_malformed_resume_delta_fails_safe_via_emit` — a malformed delta raises in `emit_result` and asserts nothing is written to the WAL.

## 🟡 Should-fix (resolved)

- [x] **no test for `in_flight: ["not-a-dict"]`** (list entry not an object) — added to rejection set.
- [x] **no test for `stage` wrong-type** (`stage: 5`) — added, for parity with `next_slice` coverage.

## 🟢 Nits (resolved)

- [x] **provider-neutrality guard didn't reach into `resume_delta`** — security. A `resume_delta` carrying `session_id`/`provider` passed (pre-existing, not a regression, but this is the contract-tightening PR). **Fix:** `_validate_resume_delta` now runs the same banned-key scan; tests added.

## Notes (no action)
